# Hark 整改分项：通知与消息

主控集成补记：CLI通知已移到任务锁外，queued也会按预算对账，message-retire已接正式短锁命令；Codex客户端分页及错误分类已集成。agent prompt说明仅适用于本分项的AGY普通消息，不适用于CBC/ZCode自报执行端。下列待集成建议保留阶段记录，最终测试以总报告为准。

## 范围

本分项处理 CORE-03、CM-05、CM-07、CM-10、CM-11，以及 CM-13 中与通知幂等 ID 有关的内容；同时核对消息正文保密、UTF-8 字节上限和重试时间戳新鲜度。原审核报告及 `hark_yotta_review/repro/` 保持只读。

实现限于 `agent-bridge/lib/notify.js`、`lib/notification-control.js`、`lib/messages.js` 与通知/消息回归测试。所有验证均使用隔离状态目录、内存队列、Herdr 调用桩和临时消息记录；未连接 Codex 队列、Herdr 服务或真实执行 Agent。

## 附录保护项核对

- **正文保密**：`publicReceipt` 不含 `text`、`rendered` 或 `marker`；事件、通知正文和错误证据不写入用户消息正文。消息未终结时，私有状态文件暂存正文，供 agy 安全边界注入及原生 transcript 对账使用；到达 `accepted`、`blocked` 或 `operator-retired` 后清除明文，只保留正文哈希和必要裁决/投递证据。
- **字节上限**：输入按 `Buffer.byteLength` 检查，正文上限为 32,768 UTF-8 字节。回归覆盖恰好 32,768 个 ASCII 字节、恰好 32,768 个 UTF-8 多字节正文及超限输入；超限请求在任何 Pane 操作前拒绝。
- **时间戳新鲜度**：通知补送冷却为 60 秒，依据持久化 ISO 时间戳计算。非法时间戳和未来时间戳均禁止自动补送，避免损坏数据或时钟偏差造成重试循环；每个事件最多 3 次添加尝试。
- **不确定消息**：`deliver` 重复请求只对账，绝不自动重投；transcript 必须匹配唯一 marker 和正文 SHA-256，终态消息清除正文但保留证据。未知结果只能经操作员 `retireMessage` 解除本地门禁，不能因此标成 delivered 或 not-delivered。

## 集成建议

1. `recoverOne` 对 `queued` 通知也调用 `notifyTask`。该函数先执行队列 list；仍 queued 时不重复添加，缺项时按事件预算和时间戳决定是否补送。
2. 新增消息 retire CLI 时，在任务锁内 fresh-load，再调用 `retireMessage`；保证 reason、evidence、actor 均为必填，并仅允许上述停止或待验收任务状态。
3. watcher 与恢复路径调用 `notifyTask` 前先完成 task 状态持久化，再释放任务锁；`notifyTask` 自行以短任务锁读改写 notification，不得在网络 RPC 期间占用任务锁。
4. 将 `operator-retired` 对外描述为“操作员记录的本地验收收口”，不转述为原生执行事实；对不确定消息继续保留无自动重发规则。
