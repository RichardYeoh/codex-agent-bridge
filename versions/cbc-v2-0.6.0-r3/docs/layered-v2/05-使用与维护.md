# CBC分层协议使用与维护

适用范围：经发布检查启用的CBC V2。ZCode、AGY、OC仍走原适配器。源码、状态、冻结产物及版本清单均保留在桥接工程或指定状态根，不依赖聊天记忆恢复。

## 日常操作

继续调用工程原`agent-bridge/bin/agent-bridge.js`。薄路由对新CBC选择已启用版本；已有任务按记录协议和版本处理，其他Agent沿用旧入口。主控仍负责明确需求和验收，低层ID、摘要、回执、快照由程序生成。

```powershell
$bridge = '<桥接工程>/agent-bridge/bin/agent-bridge.js'
$env:AGENT_BRIDGE_STATE_DIR = '<本项目状态目录>'
node $bridge dispatch --agent cbc --cwd '<项目目录>' --spec-file '<任务规格.json>' --task-id example-cbc-001 --worker-key implementation --pane '<已核实主控Pane>' --codex-thread '<主控线程>'
node $bridge status example-cbc-001
node $bridge read example-cbc-001
node $bridge ack example-cbc-001 --key '<当前通知key>'
node $bridge rework example-cbc-001 --spec-file '<修订规格.json>' --prompt-file '<返工要求.md>'
node $bridge accept example-cbc-001
```

首次任务按完整规格提供背景、范围、交付物和验收命令。deliverables必须是实际文件路径；报告与这些文件由结果命令自动冻结。失败同样提交结构化报告，不能将“无法完成”转成技术通过。

相关新任务保持worker-key并由上下文台账复用；明确原生来源时加`--resume-task <已接受来源任务>`。已关闭Pane可冷恢复同一会话。使用旧运行时的空闲Pane不热改Hook，由原主控核对并关闭后冷恢复；禁止维护者替业务操作。默认一个项目一个Workspace，明确隔离才使用`--new-workspace --isolation-reason`。

## 状态与人工操作

| 状态 | 含义与动作 |
|---|---|
| written或unknown | 仅传输事实或回执未知；不得重发，使用recover对账 |
| admitted | 精确本轮原生指针已接纳，仍未完成 |
| execution blocked | 当前请求有审批证据；核对具体权限，不自动allow |
| observation unavailable | 观察超时、原生记录不可读或观察器异常，不等于执行失败 |
| delivery_missing | 原生已结束但缺冻结交付；检查报告后正式返工 |
| review pending | 接纳、结果和Stop齐全，等待独立主审 |
| review accepted | 主控已接受冻结版本，下一次派工仍检查资源就绪 |
| conflict或contested | 矛盾证据，保留历史和资源隔离，不能强制accept |

未封装聊天和`/status`等管理操作不生成派工请求。交付后的输入不回退历史结果。执行中插入输入可能使结果归属不确定；同目录手改文件仍有真实冲突，不能承诺互不影响。`sourceDrift`表示当前源文件不同于冻结交付，应审查快照并决定后续整合。

## 恢复与停止

```powershell
node $bridge recover example-cbc-001
node $bridge resume example-cbc-001 --wait-timeout-ms 0
node $bridge reconcile-submission example-cbc-001
node $bridge cancel example-cbc-001
```

V2恢复只对账并重建本地观察，不新发正文。`wait-timeout-ms=0`为本地无期限观察，不轮询模型；有限观察到期保留执行状态，可显式续观察。通知失败保留结果，按原notifications命令恢复队列；queued、ack和accept不同。

cancel只结束有证据支持的协调，不盲发Esc、Ctrl+C或stop。精确终态或明确未发送可确认；只有执行端消失而原生结果未知时，保留`originalExecutionMayContinue`资源隔离。abandon要求主体、原因和证据，不伪装成功或释放未知后台工作。V2不支持将活动请求adopt到另一terminal；不可变绑定须保留，不能手改task.json。当前没有通用自动解除后台作业隔离的入口，需针对精确执行端证据处理。

429、配额耗尽、断网或IPC拒绝不能推出任务未执行。没有精确Stop和结构化结果时不声明完成；保留上下文，检查layers、observationDiagnostic、请求events和Hook诊断。故障不授权自动换模型、账号或重发。原生JSONL读取上限128MiB、单请求4096事件/8MiB、报告4MiB、单产物64MiB、整组256MiB；超限保留未确认，不裁剪证据冒充完整。

## 插件与配置

Herdr侧栏状态由已安装herdr-codebuddy插件提供。V2仅增加任务事件Hook，不重复注入状态插件；启动前检查插件脚本及关键事件配置。全局原桥接Hook保留旧任务兼容：独立会话和V2不再由它上报状态。不得整文件覆盖settings，也不删除旧任务仍使用的Hook。

插件侧栏不构成任务完成证明。cwd和提示词不是操作系统沙箱；桥接与执行者在同一用户权限边界，不能抵御同权限恶意进程伪造文件。不同权限需求仍须选择实际沙箱与审批模式。

## 版本与回滚

版本源码、测试和清单位于`versions/<发布ID>/`。旧CLI保存在`agent-bridge/bin/agent-bridge-v1.js`，薄入口使用同目录`layered-release.json`选版本；已有V2任务保存runtimeReleaseId，不随新默认版本切换。发布脚本默认预览，显式apply才创建全新目录，verify核对文件集及摘要，不覆盖已有版本。

回滚只将layered-release.json的enabledCBC改为false，保留版本映射和源码，使新任务回旧入口、已有V2继续完成。不得删除在途任务所用版本，不重启共享Herdr或业务Agent。版本启用记录与回滚文件保存在项目.local发布记录中。

## 故障反馈

反馈包含：发布ID、任务/轮次/请求ID、六维状态、准确命令和退出码、失败阶段、是否写入/接纳、脱敏诊断路径与摘要、有无执行在途、维护范围。保留首败和uncertain记录；原始会话、凭据及认证链接不得公开。维护只修工具，业务主控决定续办及技术验收。
