# 执行主控的工具权限与预检

## 权限规划

| 实际职责 | 需要明确的最小能力 | 不应默认推导的授权 |
|---|---|---|
| 只读审查、资料分析 | 读取指定输入；必要时写自身审查产物 | 修改生产文件、派发执行者、访问其他线程历史 |
| 编码或仿真执行 | 修改获准目录；运行指定工具及写自身输出/临时目录 | 修改判据、扩大目录、操纵共享服务 |
| 独立验证或模块执行主控 | 自身职责目录加外部执行者调度、消息和回执所需IPC | 继承创建者沙箱、写设计目录、控制其他主控的执行者 |

按任务实际需要组合能力，角色名称不是固定权限枚举。父线程的权限、HERDR_ENV、同一登录用户、Medium完整性级别或相同模型都不能证明子线程具备同等访问能力。对已有线程先查当前运行策略，不凭创建时计划或旧会话结论。

范围说明约束业务行为，操作系统策略约束工具能力；执行Agent自身的edit/yolo等参数只影响它自己的审批流程。三者不可相互替代。完整访问会扩大本机文件/网络能力，不能将其包装为仍有相同操作系统隔离；应有具体用户授权并保留业务职责边界。

## 原工具上下文预检

由将实际执行dispatch/rework/通知的线程在自己的工具中核实：

1. 当前项目、Herdr服务及已指定Pane/Workspace；不凭焦点猜测，不仅检查HERDR_ENV。
2. 实际工具沙箱、审批策略、命令路径和版本；仿真还需核实获准输出目录及工具可用性。
3. 只读Herdr IPC及目标线程metadata/队列查询。维护工程的tools/diagnose-agent-ipc.cjs提供无业务写入的诊断，结果写调用者自身私有目录。诊断包含本机身份/路径，禁止公开提交。
4. 准备启用该角色前检查所需回执链路；检查入队只证明接纳，收到执行证据才算原工具验证通过。

若由上级主控创建Codex线程，应把所需能力与已有授权一起明确传递，并核对实际生效策略。仅在平台支持且用户授权的范围内设置权限，不修改数据库或信任记录模拟授权，也不因更新Skill而重新创建稳定会话。

## 拒绝、消息与回收

PermissionDenied、EACCES、HERDR_IPC_ACCESS_DENIED或CODEX_PROXY_ACCESS_DENIED先按权限边界处理，不通过换Shell、换账号/管理员、改ACL、关闭沙箱或另起共享服务绕过。若需调整权限，先给出具体范围和影响，由用户确认；最小配置未经原环境验证时只能标为候选。

已有获准传输代理可以只代发指定官方命令并回交回执；规格、测试判据、返工决策和验收仍归原执行主控。不得为了代理权限把技术控制权转给其他线程，也不新建绕过沙箱的常驻服务或私有IPC。

向仍存活的原owner发后续消息优先只入队，不附带resume抢writer。绑定目标线程及稳定消息ID；结果不确定先查询，不重发。分清代理连接失败、线程存储读取失败、文本已入队、已消费及任务执行；no rollout found不直接等于会话已删除，其他线程的成功也不能充当本线程修复证明。

以原工具中的实际命令、退出码和私有证据收口，未完成的权限决定和实测明确保留。新会话可重新发现已安装技能；旧会话由主控提示直接读取新版文件即可，不宣称技能更新会自动改变权限或所有会话已热加载。
