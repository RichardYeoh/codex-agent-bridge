## 真实测试发现及修正

1. 第一轮Hook的prompt摘要与原生输入不同；原生JSONL内任务指针逐字一致。初版拒绝接纳，结果命令也拒绝冻结，未误报通过。修正为精确原生首输入与有序绑定Hook交叉证明，保留两个摘要；增加另一用户输入在先的拒绝测试。具体Hook文本转换原因尚未证实。
2. 原生Stop后的`idle_prompt`提醒导致就绪守卫拒绝返工。明确忽略这一通知类型；`permission_prompt`和未知活动仍保留阻塞作用。第一次返工未写入，失败记录保留。
3. 第一轮正式recover只读对账进入`delivery_missing`，没有重投、补造交付或技术accept。
4. 第二轮正式返工在原生同会话接纳，但旧等待入口只读投影、未对账延迟落盘记录，发生“working但超时”。已改为等待期间进行本地证据对账；后续新任务实测派工退出0且自动待审。180秒测试观察期限到达只记观察不可用，执行保持running，未停远端。
5. 重投Hook、观察记录乱序、矛盾传输回执、资源释放后迟到活动、坏JSONL静默失败、abandon被恢复投影覆盖及路径别名均已有定向修正和回归。错误只存类别，不将原生JSON解析行写进诊断。
6. 新任务可复用验收后的同一原生会话；关闭测试Pane后可冷恢复同一ID。真实普通聊天完成后，已冻结事件摘要保持不变，正式accept成功。
