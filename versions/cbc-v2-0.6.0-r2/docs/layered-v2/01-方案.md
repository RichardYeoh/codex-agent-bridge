# 分层任务协议重构方案

状态：方案确定，开发隔离中；未发布。版本目标：0.6.0。

## 目标与范围

Herdr提供执行承载和基础信号，消息接纳、任务交付、技术验收分别由独立证据驱动。首个完整适配对象为CBC，保持原生TUI、原会话返工和当前主控操作入口；ZCode、AGY、OC保留现有路径和扩展契约，不伪称已迁入新协议。旧任务不自动改写历史。

线上工作树和已安装Hook在验证结束前保持不变。隔离开发基线为a27a6d2加用户已知CBC-GUARD/ACCEPT工作树修改，完整逐文件摘要另存私有baseline.json；Hark复审资料只读保留。发布检查须比较当前线上字节，防止覆盖开发期间新增修复。

## 需求

| 编号 | 要求 | 判定 |
|---|---|---|
| R01 | 任务身份独立于Pane与会话当前焦点 | 任务/轮次/请求/规格摘要绑定；重建不换请求 |
| R02 | 一次逻辑请求有明确接纳及结果 | 写入、排队、接纳、交付、验收分开 |
| R03 | 未封装操作不更新派工任务 | 原生无关输入只影响资源准入与冲突；不改已冻结交付 |
| R04 | 断网不等于执行失败 | 观察健康与执行状态正交；未知不重放 |
| R05 | 已交付事实不被后续消息抹除 | 保存不可覆盖的本轮证明及产物快照 |
| R06 | 状态处理由程序决定 | Schema、状态迁移、幂等、摘要、重启恢复均不用模型推理 |
| R07 | 保护审批和人工接管 | 不自动批准/全局stop，不把手动工作倒配旧请求 |
| R08 | 任何拒绝均有诊断与正式出口 | 诊断/观察恢复/明确未发送取消/隔离关闭；未知不得假关闭 |
| R09 | 可发布和回滚 | 分版本入口，旧任务锁定旧协议，新任务默认经验收版本 |

## 分层

| 层 | 输入与输出 | 状态所有者 |
|---|---|---|
| 承载 | Pane、terminal、native、PID出生时间、连接健康 | Herdr/适配器 |
| 消息 | request_id、message_id、reply_to、摘要及接纳证据 | 消息日志 |
| 任务 | 明确阻塞原因、交付声明、冻结产物和精确原生结束 | 任务协议内核 |
| 验收 | 已冻结结果和主控决定 | Codex/用户 |

不再用一个blocked表示IPC断开、资源限流、模型等审批和技术不能完成。信用分本阶段不控制正确性：先积累原因明确的统计，网络/配额不计技术质量扣分；任何分数均无权跳过身份与验收。

## 外部参考与适配边界

A2A区分context、message、task及任务终态；CloudEvents以source+id去重。采用这些语义，不宣称本地CLI是A2A兼容服务。桥接的task/round对应业务与执行轮次，返工新round、新request，旧终态只追加引用而不重启。参考：https://a2a-protocol.org/v0.3.0/topics/life-of-a-task/ 与 https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md 。

CBC缺少原子任务API，因此仍需Hook/原生记录适配；结构化模型声明只是结果声明，不能证明接纳、后台进程退出或技术正确。共享用户权限下不构成对恶意同用户进程的安全沙箱。

## 阶段门禁

方案→设计→内核及CBC接法→隔离回归/真实CBC→发布维护。每阶段记录完成证据；模型不能以测试数量代替安全不变量。未通过真实CBC和迁移回滚验证不得切换线上。
