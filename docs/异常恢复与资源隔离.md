# 异常恢复与资源隔离

适用版本：0.5.0工作树，Hark审核整改。下述命令均须先设置原任务的`AGENT_BRIDGE_STATE_DIR`。`$bridge`指向本检出目录的`agent-bridge/bin/agent-bridge.js`。所有状态迁移通过协调器完成，不手工修改task.json。

## 恢复顺序

先读取`status <任务ID>`及当前轮交付。`recover <任务ID>`执行只读原生对账、修复缺失观察器及通知对账；不会自动重发业务提示。原生API或Herdr暂时不可达不构成执行失败证明，已有running及存活watcher保留。

普通`resume`仅恢复原会话与观察。只有round 0明确尚未投递时才提交首次任务。已提交轮次即使重建Pane也不重放；`--force`只允许显式选择恢复位置，不授权绕过身份、不确定提交或重复投递。原会话在其他Pane恢复时，使用下列命令重新绑定，不启动第二个TUI：

```powershell
node $bridge adopt-restored <任务ID> --pane <核实后的PaneID>
node $bridge observe <任务ID> --wait-timeout-ms 7200000
```

`adopt-restored`核对官方原生会话引用、执行端类型、terminal、冲突任务及Pane租约。`observe`调整监听上限并更换观察器代次；不生成业务命令。旧观察器的迟到结果不能覆盖新代次。`--wait-timeout-ms 0`为不限观察等待，不代表模型任务可无限重试。ZCode观察仍由本地wrapper附着原command，不能与网页远控争抢Relay。

## 明确失败与迟到交付

OC当前轮已发生新的原生failed终态、无活动/审批/表单/外来输入且归属核实后，可显式重试同轮同一任务书：

```powershell
node $bridge resume <任务ID> --retry-failed
```

每轮最多两个追加尝试，各有持久化稳定准入ID。丢失准入回执时先`recover`按Inbox或精确用户消息ID对账，禁止换ID重发。历史失败不能当作当前轮失败；普通resume不触发失败重试。审批、网络和配额故障不自动升级模型。

晚到的非空指定交付可用`settle <任务ID>`重新申请主审。只有当前轮原生完成证明通过才转review_pending，文件存在本身不构成证明；该命令不会accept技术结果。

## 取消与协调退出

`cancel`请求停止，`recover`仅确认。OC允许在Pane缺失时凭当前轮准入、原生会话/目录、租约及稳定回合指纹执行有界中断；审批、外来输入、身份变化均拒绝。重复显式cancel最多三次尝试，间隔至少一秒，每次重验同一回合；recover不发送中断。

CBC/AGY没有经验证的命令级取消API。执行者仍在时保留cancel_pending，主控核实现场后停止或关闭确切执行Pane，再recover核对执行端已消失。此证明仅确认登记执行端结束，不保证脱离终端的后台仿真等子进程已经退出。ZCode锁定SDK缺少可验证的command条件停止，因此不自动调用会话全局stop；已有精确原生命令终态可按支持证明收口，其余情况保持未知。

启动前有持久化“无副作用”边界且无会话、Pane、提交或存活启动者时，可通过cancel关闭申请；边界不完整时不能靠空ID推断未启动。

无法安全确认原生终态、且本地观察器已退出的任务，可由获授权主控提交理由、操作者和证据文件：

```powershell
node $bridge abandon <任务ID> --actor <主控标识> --reason <原因> --evidence-file <核对证据文件>
```

状态abandoned仅表示结束本地协调，原生结果仍未知。历史、会话及证据摘要保留；原生会话、Pane/terminal、Relay和可能重叠写入范围继续隔离。同一项目其他无冲突范围可接续，独立项目不被全局锁住。不能换worker-key或新root规避隔离。重新找到精确存活所有者后可用adopt-restored恢复观察；隔离解除须有真实归属/终态证据。

## 消息与通知

任务已终结且不可能继续执行，但旧纠偏消息投递状态无法完全确认时，可用`message-retire`保留人工处置记录，使accept/rework不永久受阻：

```powershell
node $bridge message-retire <任务ID> --message-id <消息ID> --actor <主控标识> --reason <原因> --evidence <证据说明>
```

退役只关闭该消息的本地协调义务，不声称消息已接纳、未送达或已撤回。running、blocked、cancel_pending及原执行可能继续时均拒绝。

通知区分queued、consumed和acknowledged。队列项消失仅说明已离队；无ack时经冷却和持久化预算可有限提醒。只读查询失败不当作写入不确定；未知写入先对账。任务状态先在短锁内落盘，网络队列调用在任务锁外执行，迟到回执须重新核对轮次和事件key。

## 验证边界

新增回归使用隔离状态目录、官方API形状的替身和真实本机子进程锁；不代表已操作真实业务会话。Windows Herdr更新后的真实恢复环境、双官方集成共存及云端通知链路仍需独立窗口验证。复审条目、命令和实际结果统一见`hark_yotta_review/整改结果.md`。

## CBC发送前拒绝与旧记录对账

Herdr的named/idle状态不证明`agent prompt`可用。0.9.5实现还要求内置执行端识别；自定义CBC Hook不能通过改名取得该能力。CBC改为执行端专用的guarded Pane.run：核对本轮待发记录、原生Hook空闲边界、租约、可见审批界面和实际进程，并重复验证PID/创建时间及状态稳定，随后只提交一次原子文本加Enter。不能将此过程声称为跨RPC原子状态比较；外部人工同时操作窗口仍有竞态风险，证据缺失时禁止输入。ZCode自写包装器同样采用专用输入；AGY保留真实agy内置标识走可验证的原生输入。

新记录对`agent_not_ready`等明确发送前拒绝保存独立attempt journal，回滚至提交前轮次和主审状态。下一次显式提交使用新attempt，不覆盖首败证据。超时、丢失写入回执及写入后身份错误保持unknown，不自动重发。

旧版已误记submission_unknown的CBC任务可只读核实原始回执：

```powershell
node $bridge reconcile-submission <任务ID> --rejection-receipt <首次CLI回执JSON>
```

只在raw RPC类型、精确拒绝、task/round/Pane、历史、事件及原始CLI失败回执交叉一致时返回not_sent；未知或冲突返回unresolved。命令不修改业务task、历史或原生会话。旧无journal格式采用独立legacy证明，不把新格式缺失当成未发送。MSYS2环境前缀只接受白名单字面配置和原状态根匹配；不执行回执中的命令。

若主控明确决定结束这条旧协调记录，可使用：

```powershell
node $bridge abandon <任务ID> --rejection-receipt <首次CLI回执JSON> --actor <主控标识> --reason <处置理由>
```

该操作保留旧submission和历史，另记未发送证明，状态仅为abandoned；原生Pane即使仍在执行其他工作也不被停止、重载或投递。资源隔离继续生效，不得当作“原生空闲”或通过换绑定再次派发同一内容。存在用户直发任务时先按其独立intent/receipt核实，不得重复旧任务；源文件变化须由业务主控重新冻结后再决定接续。

CBC启动入口和原生校验目标分开保存，支持工程内仅追加窗口预设的.ps1启动包装器；实际进程仍须匹配已知CodeBuddy Node及包脚本，不能把powershell或cmd本身当作CBC。新dispatch保存cbcBinary/cbcNativeBinary/nodeExecutable，旧任务则在显式调用者配置与真实进程证据均通过后才准入；不修改用户启动脚本或全局入口。


Herdr 0.9.5的agent_session及completion_seq为可选字段。CBC输入guard依赖精确原生Hook、租约及当前进程证明身份；存在的原生引用冲突仍拒绝。state_change_seq单独保存为状态稳定基线，不冒充完成序号。发送前明确拒收且回滚为failed/r0、submission为空时，在原生空闲及身份门禁重新通过后，可由主控普通resume首次提交；保留首败journal，不用force。极短回合凭本轮提交后原生Hook确认活动，不凭状态序号增长推断完成。真实环境补修证据见hark_yotta_review/MC039-CBC元数据兼容补修.md。


## CBC已执行但回执不确定

新轮次`cbcTurnProtocol:1`可通过精确原生输入自动对账丢失回执，观察器异常后`recover`只重附观察。发送者崩溃遗留`sending`也必须取得精确原生证明才能转observed，否则保留submission_unknown，不允许重投。详细操作与兼容边界见[CBC精确回合与恢复](CBC精确回合与恢复.md)；旧历史不批量改写。

新增`reconcile-submission <id> --cbc-transcript <原native.jsonl绝对路径>`只读核实原生指针、attempt、原提示SHA及绑定Hook；`recover <id> --cbc-transcript <同文件>`在实时身份/租约/状态/进程双次核验后正式对账，不发送或重投正文。活动原回合只启动本地watcher；原输入后的精确Stop加指定报告进入review_pending，无报告delivery_missing，审批blocked。原attempt保持uncertain历史，另存对账回执。不得把后来问答或其他工作Stop套给原输入；当前原生忙碌/审批或身份变化时拒绝。recover返回数组中的error必须检查，退出0不单独证明成功。详见hark_yotta_review/MC039-CBC不确定提交对账.md。
