# 迁移与持续维护

## 归属与范围

协作系统从CBC初建工程中独立出来，由Codex主导维护。当前检出目录包含有效输出、公开过程证据、独立工作约定和Git历史。后续业务开发、Agent接入、技能更新与验收均在这里接续。

旧工程还包含另一项CBC私域配置迁移工作。清理按归属执行：仅移除协作系统源码、测试工程、审计目录、交接文档和对应会话段落；旧工程AGENTS中的非本项目规则、9月会话记录和通用CBC会话保留。不能仅因进程参数中出现旧目录就判定为本项目。

## 保留的资料

迁移前全部2302个文件已在.local/source-before-migration.zip中完整归档，逐文件SHA256验证通过，清单位于.local/source-manifest.json。归档只存在于迁移机器，不上传GitHub，亦不能替代独立异地备份。

运行状态副本保存在.local/audit/2026-10-27/state，路径已调整；两个真实审计任务均accepted，通知已暂停。早期测试状态在.local/legacy-test-state，按历史证据保存，不默认恢复未验收的旧任务。旧IDE恢复指针位于.local/legacy-ide，只作历史材料，不代表新目录可以沿用IDE工作区身份。

公共记录中的运行标识、账户目录和本机绝对路径已经替换；原始字节仍保存在本地归档。下载的ZCode源码和缓存未重新发布，公开证据只保留来源、校验信息和实验结果。

## 维护责任与接口

Codex拥有规划、派工及最终验收权。执行Agent可新增，但必须完成adapter-contract.md中的实际接口验证。CBC的会话、模型参数和终端事件属于执行端适配范围；轮次、状态、通知、返工及验收仍由协调器管理。

技能源使用安装占位符，运行副本绑定真实检出路径。迁移时只更新CBC配置中属于本工程的Hook命令，不修改无关Provider、信任目录和其他Hook。运行中的CBC和watcher不会热更新所有已加载模块，需先核对在途任务再安排重启或恢复。

发布前至少运行npm test、npm run test:e2e，检查待提交文件中的凭据与本机路径，确认.local和node_modules未跟踪。影响Herdr/CBC/Codex集成的升级还须实际跑一次委派、返工、通知及恢复。

## 待补验证

- 新版原生队列在Codex空闲时自动启动验收轮。
- 组件升级后的真实兼容性、整机重启、全部权限/取消分支。
- ZCode正式Provider、认证和模型调用，再决定最小执行适配器；不修改安装包，不复制受保护桌面凭据。

上述未验证事项须保留在进度台账，不得因迁移或Git发布改记为通过。

## 发布及清理结果

首次提交已推送main，远端提交与本地一致。通过GitHub重新克隆到本机干净目录后，npm ci、38项自动回归和8项交付验收再次通过；首次提交的GitHub Windows工作流也已通过。

旧位置的本项目文件使用可恢复搬迁方式移入.local/migrated-owned，原始完整ZIP仍保留。此前递归删除被自动安全策略拒绝，未执行；没有为清理而关闭Herdr或Codex常驻服务。旧目录中两个混合文档的非本项目前缀已按原始字节保留并校验SHA256一致。

仍有两个被占用的空目录agent-bridge和agent-bridge-test留在原位置，均已确认零子项；它们不再承载代码或数据。另一个管理员权限启动的历史故障测试服务无法从当前普通终端核实，不强制关闭。待占用解除后，可核对仍为空再移除这两个目录，不使用递归删除处理残留。

本次迁移不代表清理了Agent平台的原生历史会话；该类存储可能承载其他任务，未批量修改。未能确认归属的旧会话保留，避免因目录引用相同而误伤其他工作。
