# 上下文复用与面板布局

## 上下文选择

会话按工作上下文的连续性复用，由Codex在任务分析和delegate-worker中判断，不由工具预设角色或任务类型分类。角色名称、任务类型、涉及模块、文件范围与历史交付均可作为线索。同一模块的连续实现、调试和补测试通常沿用原会话；无关目标、冲突背景、需要独立视角的验证或用户明确要求多个执行者时，才分开。

用户无需每次强调“继续原会话”。派工前查询sessions，读取已有目标、范围及sessionId，选择已有worker-key。该键是不透明的稳定绑定标识，不是角色枚举；不可按每轮任务ID生成新键。默认primary与旧版本单上下文台账兼容；更换阶段或角色称呼不应自动更换绑定。具体模块通过任务规格描述，cwd保持项目根目录。

工具保存项目目录、执行端、Herdr服务、worker-key及真实原生sessionId。存活且身份匹配时直接复用Pane；Pane已关闭时，在原项目Workspace按保存ID重新拉起原生会话，并核实新终端的session回执。身份核实后允许继续使用增量提示；压缩、背景或规则变化时恢复完整提示。连接错误、原执行仍忙或占用者不符时停止核对，不自动创建另一个空白会话规避问题。

未再次显式指定模型、推理强度或权限选项时，继续使用绑定中保存的执行参数，不因调用参数省略而创建另一个默认配置的会话。显式变更参数时检查兼容性，再决定是否需要新会话。

每个绑定同时只持有一个未闭合任务，待验收和执行状态不确定也不能被新任务挤占。原生会话数据已丢失或恢复失败时，保留状态并由Codex决定如何重建，不把恢复失败写成已延续上下文。

## 用途命名与验收后退出

用途命名和验收后退出由Codex的delegate-worker流程执行，不要求各原生工具提供统一重命名或退出接口。首次派工由Codex按任务类型、模块或持续职责选择用途短名，例如“RTL实现”“JPEG仿真验证”；这些只是示例，不形成工具中的角色枚举。

Herdr注册名保留协调器分配的cbc、agy、oc等唯一名称，Pane标题显示“注册名 · 用途短名”，多实例可显示“cbc-2 · 接口验证”。只修改Pane可读标题，不在协调器之外修改Agent注册名，避免破坏身份核对。原生CLI或Desktop是否支持修改会话标题不影响这一流程。

用途以worker-label.txt保存在任务状态目录，与worker-policy.md同目录。后续通过sessions的lastTaskId定位上次用途，复用同一绑定时默认保留；需要调整时由Codex判断，不因标题变化另建会话。恢复或返工创建新Pane后重新应用用途标题。登记文件留在本机状态目录，不把真实会话标识写入公开仓库。

验收通过后，Codex先accept并核对任务和上下文台账已保存真实会话ID，再检查对应Pane的服务、terminal、Agent类型、当前租约及空闲状态。确认没有待处理审批或未收敛后台工作后，仅关闭本任务拥有的执行Pane，结束本次终端运行。任务、交付、用途和原生会话历史保留，相关任务以后按登记ID重新拉起。用户明确要求保留窗口时可保留；身份或执行状态不确定时不关闭并说明原因。

当前accept命令本身不自动关闭Pane，这一步由Codex执行；直接手工运行accept只完成验收记账。关闭Pane不删除会话，不退出账号，不停止OpenCode共享服务或ZCode Desktop，也不关闭整个Workspace。该默认策略不用于批量关闭归属不明的历史窗口。

## Pane与Tab分配

Codex主Pane是明确的布局锚点，固定保留在主标签左半屏，完整占用该页高度，右侧分配后不再拆分Codex主Pane。没有执行者时Codex可占整页。创建操作不改变用户焦点，不新建项目Workspace，也不搬动或拆分归属不明的用户Pane。

| 执行者数量 | 主标签 | 新增执行标签 |
|---|---|---|
| 1 | Codex左半，执行者1右半 | 无 |
| 2 | Codex左半不变，右侧执行者1/2上下 | 无 |
| 3 | 保持不变 | 第2标签：执行者3整页 |
| 4 | 保持不变 | 第2标签：执行者3/4左右 |
| 5 | 保持不变 | 第2标签：左侧3，右侧4/5上下 |
| 6 | 保持不变 | 第2标签：左侧3/6上下，右侧4/5上下，形成四格 |
| 7至10 | 保持不变 | 第3标签重复整页、左右、右侧上下、四格 |
| 后续 | 保持不变 | 每个执行标签最多4格，然后增加标签 |

数量按实际占用的执行Pane计算；仍存活的原Pane可以复用，不按调用次数新增。验收后通常已关闭执行Pane，相关任务按原会话ID创建新的运行Pane并使用空出的容量；会话复用不等于必须保留同一Pane。既有用户手工布局不自动重排，不符合当前分配形态时使用新的执行标签。--pane应指向主控Pane；仅有Workspace时必须有唯一可识别Codex锚点，不能依赖焦点。--split-direction不能绕过主控半屏保留规则。

## 明确要求并行时

默认仍为单任务串行。用户明确要求例如“5个CBC并行实现5个模块”时，Codex为每个子任务选择独立的稳定绑定，传--parallel与--worker-key，并先分配互不重叠的明确文件或目录。公共集成文件由主控修改。后续同模块任务可继续复用这些会话，不每次重建。

同一个ZCode Desktop Relay绑定只有一个terminal席位，不能用多个Pane竞争同一席位；当前应串行执行这些ZCode任务。并行选择属于编排决定，不能因用户举例或工具支持并行而自行启动多个模型。

## 维护与验证

上下文选择原则在delegate-worker；不透明键在worker-binding；上下文记录与恢复计划在worker-context；串行/明确并行约束在worker-scheduling；实际布局在location。所有任务继续使用公共的轮次、通知、返工与Codex验收流程。

真实验证包括隔离空终端从1到10个执行Pane的几何检查，以及CBC/ZCode关闭Pane后跨任务恢复原session并凭记忆交付。空终端布局测试不消耗模型额度。并行5路的绑定与写入范围约束通过自动回归，未为验证此规则实际启动5个模型。详细证据见evidence/2026-10-27-context-layout。
